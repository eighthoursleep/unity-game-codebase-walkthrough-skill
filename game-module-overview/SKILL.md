# AboutMe 模块清单生成

为指定代码目录生成一份"模块清单"md 文件：一张编号表格，每行一个模块，含路径、一句话职责、（若存在）指向 `AboutMe/` 模块文档的链接。本 skill 取代旧版"子模块总索引（含依赖关系图）"的产出，口径以 AboutMe 现存清单为准。

## 第 0 步：先读样板对齐口径

动手前必须先读目标层的现存清单（若已有）以及 `AboutMe/` 下任意一个已成形层的清单——它们是格式的真源，本轮产出的格式必须与之一致。注意不同层可能是不同的列数变体（如 4 列：序号｜模块｜路径｜职责说明，或 3 列：序号｜模块名｜职责说明，链接以 `。[模块文档](...)` 内联）。**目标层已有清单时，沿用该层自己的列结构，不要套别的模板**。

同时确认两件事：

1. **输出文件位置**：清单就是层目录自己的 README——`AboutMe/<层名>/README.md`。若用户指定了别的落点，以用户为准。
2. **被扫描的代码根**：用户会给（如某个业务/框架/工具层目录）。不给就根据层名推断并向用户确认一句。

## 产物格式（4 列标准版）

```markdown
# <层名>模块清单

| 序号 | 模块 | 路径 | 职责说明 |
| --- | --- | --- | --- |
| 1 | BattleCmd | `Battle/BattleCore/BattleCmd/` | 帧同步战斗指令（B2C/C2B 指令定义、ByteBuf 序列化）｜[模块文档](./战斗内核/03-协议与传输/README.md) |
| 2 | Camera | `Battle/ExpressionScripts/Camera/` | 战斗相机表现（13 个） |
```

格式细则（都是既有清单的既成口径，不要发明新写法）：

- **路径**列：相对被扫描代码根的路径。目录以 `/` 结尾；散文件写全文件名（含扩展名）。
- **职责说明**：一句话，中文，说清"这是什么+关键类名或子构成"。目录下源码文件数量 ≥5 时在末尾标注 `（N 个）`。不要写成多行，不要堆砌文件名清单——列 2~4 个代表性类名即可。
- **文档链接**：仅当 `AboutMe/<层名>/<模块>/` 下存在文档时追加。4 列版用全角竖线 `｜` 接在职责说明后，链接文本统一 `[模块文档]`；3 列版在句号后内联。
- **链接中的特殊字符必须 URL 编码**（`#` 写成 `%23`，`：` 等非 ASCII 字符同样处理），否则 markdown 链接会被截断。生成后抽查至少 3 条链接确实能指向真实文件。

## 模块粒度规则

1. 代码根的**每个一级子目录 = 一个模块**；根下的散文件聚合为一行，模块名 `<目录名> 根`，路径写根目录。
2. **大模块展开**：一个一级目录含 >20 个源码文件或其子目录本身是独立子系统时，其下级目录也各成一行。父目录自身保留一行，模块名带 ` 根` 后缀。是否展开、展开到第几层，拿不准时先报给用户确认切分方案。
3. **整目录死代码**也要列（若有此先例），职责说明里注明"全文件注释作废"之类的事实。
4. 模块按**逻辑职责**命名与归并：类名前缀/命名空间相同的一组类属同一模块，不按目录机械罗列；目录仅供参考。

## 生成步骤

1. 用 Glob 列出代码根下全部一级目录与根散文件；对每个模块 Glob 统计源码文件数量（按该层语言数对应扩展名，如 `.cs`/`.lua`/`.ts`/`.cpp`/`.gd`）。
2. 逐模块确定职责：抽样读 1~3 个关键文件（类名、头注释、主入口）概括用途，不要靠目录名猜。目录很大时优先读名字像 Manager/Root/Main/Ctrl 的文件。
3. 查文档：检查 `AboutMe/<层名>/<模块>/` 下是否存在 `README.md` 或 `00-*.md`，存在则按上述格式回填链接。
4. 写出 README。若目标文件已存在，走"更新"流程（见下）。
5. 自检：
   - 表内序号从 1 连续递增；
   - 每条文档链接指向的文件真实存在（用 Glob 验证）；
   - 代码根下每个一级目录都出现在表中，无遗漏；
   - 链接中的特殊字符（`#` 等）全部已 URL 编码。

## 更新已有清单（差异式，不整表重写）

目标 README 已存在时，以既有行为准做 diff，而不是推倒重来：

- 路径未变的行：**保留原编号、原职责说明、原链接**，即使你重新概括会写得更好——既有清单经过用户逐项校对，措辞是契约。
- 新增模块：追加到表末，编号续排（不要为"好看"重排全部序号）。
- 消失的模块：先报告再删行，**不要静默删除**——`AboutMe/` 未纳入 git，删错不可恢复。
- 职责描述与代码明显不符（如模块已重命名、数量变了）时，改写该行并在回复里逐条列出改动点。

## 边界与禁止

- 只做"清单"，不做模块内部内容分析，也不做子模块间依赖关系图。用户要深挖某个模块时不要用本 skill 硬套。
- 本 skill 只写/改清单这一个文件，不创建、不移动任何 AboutMe 文档，也不删除任何文件。
- 工程树非常庞大，统计数量一律用 Glob 结果，不要试图通读源码。
